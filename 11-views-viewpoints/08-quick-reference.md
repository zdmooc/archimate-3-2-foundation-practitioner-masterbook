# Quick Reference — Views & Viewpoints

## Chaîne mentale

```text
Stakeholder → Concern → Viewpoint → View → Model
```

## Distinctions

```text
Viewpoint = HOW TO BUILD
View      = WHAT YOU SEE
Concern   = WHY THE VIEW EXISTS
Stakeholder = WHO CARES
```

## Sélection rapide

| Besoin | Vue / Viewpoint |
|---|---|
| Drivers, goals, direction | Motivation / Strategy |
| Capacités | Capability |
| Création de valeur | Value Stream |
| Organisation | Organization |
| Processus | Business Process Cooperation |
| Offre / contrats | Product |
| Coopération applicative | Application Cooperation |
| Business ↔ Application | Application Usage |
| Structures de données | Information Structure |
| Plateformes | Technology |
| Application ↔ plateforme | Technology Usage |
| Déploiement | Technology / Deployment |
| Baseline → Target | Migration |
| Work Packages / Deliverables | Implementation & Migration |
| Dépendances multi-couches | Layered / custom cross-layer |

## Règles

1. Commencer par le stakeholder.
2. Écrire le concern.
3. Formuler une question unique.
4. Choisir le viewpoint.
5. Montrer seulement le nécessaire.
6. Garder un niveau d’abstraction cohérent.
7. Préserver la sémantique et les relations du modèle.
8. Tester la lisibilité.

## Anti-patterns

```text
Poster total
Spaghetti
Trop de détails
View sans stakeholder
Diagramme décoratif
Incohérence de noms
Relation inventée
```

## Phrase à retenir

> **Une vue est une réponse ciblée à un concern, pas un export du modèle complet.**
