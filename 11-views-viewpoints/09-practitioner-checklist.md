# Practitioner Checklist — Views & Viewpoints

Avant de valider une vue ArchiMate, vérifier :

## Stakeholder & Concern

- [ ] le stakeholder principal est identifié ;
- [ ] son concern est explicite ;
- [ ] la décision ou la question attendue est claire.

## Viewpoint

- [ ] le viewpoint choisi correspond au concern ;
- [ ] un viewpoint standard a été adapté si nécessaire ;
- [ ] le niveau d’abstraction est cohérent.

## Contenu

- [ ] chaque élément contribue à répondre à la question ;
- [ ] les détails inutiles sont masqués ;
- [ ] les noms sont cohérents avec le modèle partagé ;
- [ ] les relations sont valides et correctement orientées ;
- [ ] aucune relation n’est inventée uniquement pour améliorer le dessin.

## Lisibilité

- [ ] le sens de lecture est évident ;
- [ ] les lignes croisées sont limitées ;
- [ ] le nombre d’éléments reste adapté à l’audience ;
- [ ] les zones/layers/domains sont visuellement compréhensibles ;
- [ ] une légende existe si elle apporte une vraie valeur.

## Cross-layer

- [ ] seules les couches nécessaires sont montrées ;
- [ ] les dépendances cross-layer expliquent réellement le concern ;
- [ ] les relations dérivées éventuelles sont justifiables.

## Transformation

- [ ] Baseline, Transition et Target sont distingués si nécessaire ;
- [ ] les gaps sont visibles lorsque la question porte sur la transformation ;
- [ ] les work packages et plateaus sont utilisés au bon niveau.

## Test final

- [ ] un stakeholder peut comprendre la conclusion principale en moins d’une minute ;
- [ ] la vue permet une décision, une analyse ou une communication précise ;
- [ ] si la vue reste trop dense, elle est scindée en plusieurs vues ciblées.

> **Practitioner = choisir la vue qui sert la décision, pas celle qui montre le plus de choses.**
