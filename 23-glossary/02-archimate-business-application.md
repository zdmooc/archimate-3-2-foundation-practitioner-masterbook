# ArchiMate — Business & Application

Glossaire des concepts ArchiMate 3.2 des couches **Business** et **Application**, avec les distinctions utilisées dans les architectures de paiement.

**22 termes.** Chaque ligne fournit traduction, définition, exemple MayaBank, piège et renvoi.

| English | Français | Définition | Exemple MayaBank | À ne pas confondre | Voir |
|---|---|---|---|---|---|
| Business Actor | acteur métier | Entité organisationnelle ou humaine capable d’agir. | MayaBank Payments Department ou Corporate Customer. | Business Role : Actor = qui ; Role = responsabilité. | [05-business-layer](../05-business-layer/README.md) |
| Business Role | rôle métier | Responsabilité ou fonction qu’un acteur peut porter. | Fraud Analyst ou Settlement Manager. | Business Actor : un même acteur peut porter plusieurs rôles et un rôle peut être réaffecté. | [05-business-layer](../05-business-layer/README.md) |
| Business Collaboration | collaboration métier | Agrégation de plusieurs éléments actifs métier coopérant pour un comportement commun. | Une Payment Operations Team associant plusieurs rôles. | Business Actor : la collaboration met l’accent sur la coopération, pas sur une entité unique. | [05-business-layer](../05-business-layer/README.md) |
| Business Interface | interface métier | Point d’accès par lequel un service métier est disponible. | Un guichet ou point de contact de support paiement. | Business Service : l’interface est le point d’accès ; le service est ce qui est fourni. | [05-business-layer](../05-business-layer/README.md) |
| Business Process | processus métier | Comportement métier structuré dans le temps ou selon une séquence. | Execute Instant Payment. | Business Function : Process = séquence ; Function = regroupement par finalité. | [05-business-layer](../05-business-layer/README.md) |
| Business Function | fonction métier | Comportement métier regroupé selon une finalité ou responsabilité durable. | Fraud Management. | Business Process : la Function n’implique pas nécessairement un ordre temporel. | [05-business-layer](../05-business-layer/README.md) |
| Business Interaction | interaction métier | Comportement collectif réalisé par plusieurs éléments actifs métier. | Joint Fraud Review. | Business Process : l’interaction souligne la coopération entre participants. | [05-business-layer](../05-business-layer/README.md) |
| Business Event | événement métier | Fait métier représentant un changement d’état ou déclenchant un comportement. | Payment Request Received. | Application Event : le niveau métier décrit le fait du point de vue du business. | [05-business-layer](../05-business-layer/README.md) |
| Business Service | service métier | Comportement métier explicitement exposé à un consommateur. | Instant Payment Service. | Business Process : le process réalise le service ; le service est l’offre comportementale externe. | [05-business-layer](../05-business-layer/README.md) |
| Business Object | objet métier | Concept passif pertinent pour le métier. | Payment Order. | Data Object : Business Object = concept métier ; Data Object = représentation logique applicative. | [05-business-layer](../05-business-layer/README.md) |
| Representation | représentation | Forme perceptible d’un objet métier. | Payment Confirmation PDF. | Business Object : la représentation matérialise la manière dont l’objet est perçu. | [05-business-layer](../05-business-layer/README.md) |
| Contract | contrat | Spécification formelle ou informelle d’un accord entre parties. | Instant Payment Contract. | Product : un Product peut agréger des services et contrats mais n’est pas le contrat lui-même. | [05-business-layer](../05-business-layer/README.md) |
| Product | produit | Ensemble cohérent de services et éventuellement de contrats offrant de la valeur. | Instant Payment Product. | Business Service : un produit regroupe une offre ; un service décrit un comportement fourni. | [05-business-layer](../05-business-layer/README.md) |
| Application Component | composant applicatif | Unité logicielle modulaire, remplaçable et déployable au niveau logique. | Payment Orchestrator. | Application Service : Component = structure logicielle ; Service = fonctionnalité exposée. | [06-application-layer](../06-application-layer/README.md) |
| Application Collaboration | collaboration applicative | Ensemble de composants applicatifs coopérant pour réaliser un comportement commun. | Payment Processing Suite. | Application Component : la collaboration représente la coopération entre composants. | [06-application-layer](../06-application-layer/README.md) |
| Application Interface | interface applicative | Point d’accès par lequel un Application Service est disponible. | Payment REST API. | Application Service : Interface = où/comment accéder ; Service = ce qui est fourni. | [06-application-layer](../06-application-layer/README.md) |
| Application Function | fonction applicative | Comportement applicatif interne regroupé par finalité. | Payment Validation. | Application Process : Function = regroupement ; Process = séquence. | [06-application-layer](../06-application-layer/README.md) |
| Application Process | processus applicatif | Séquence de comportements applicatifs produisant un résultat. | Process Payment Instruction. | Application Function : le Process met l’accent sur l’ordre et le flux d’exécution. | [06-application-layer](../06-application-layer/README.md) |
| Application Interaction | interaction applicative | Comportement collectif réalisé par plusieurs composants ou collaborations applicatives. | Fraud Check Coordination. | Application Process : l’Interaction met l’accent sur la coopération. | [06-application-layer](../06-application-layer/README.md) |
| Application Event | événement applicatif | Fait ou changement d’état au niveau applicatif. | Payment Authorized. | Data Object ou Kafka Topic : l’événement est le fait, pas le message ni le canal. | [06-application-layer](../06-application-layer/README.md) |
| Application Service | service applicatif | Fonctionnalité applicative explicitement exposée à des consommateurs. | Payment Orchestration Service. | Application Component ou Interface : Service = quoi ; Component = qui l’implémente ; Interface = point d’accès. | [06-application-layer](../06-application-layer/README.md) |
| Data Object | objet de données | Information logique utilisée ou produite par des comportements applicatifs. | Payment Transaction. | Business Object ou Artifact : Data Object est logique et applicatif ; Artifact est concret/déployable. | [06-application-layer](../06-application-layer/README.md) |
