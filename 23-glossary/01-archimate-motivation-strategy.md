# ArchiMate — Motivation & Strategy

Glossaire des concepts ArchiMate 3.2 utilisés pour expliquer **pourquoi** l’entreprise change et **ce qu’elle doit savoir faire**.

**14 termes.** Chaque ligne fournit traduction, définition, exemple MayaBank, piège et renvoi.

| English | Français | Définition | Exemple MayaBank | À ne pas confondre | Voir |
|---|---|---|---|---|---|
| Stakeholder | partie prenante | Personne, groupe ou organisation ayant un intérêt dans l’architecture et portant des concerns. | Le CISO est stakeholder de la résilience et de la sécurité des paiements. | Business Actor : un stakeholder est défini par son intérêt/concern, pas seulement par sa capacité à agir. | [03-motivation](../03-motivation/README.md) |
| Driver | facteur moteur | Condition, pression ou force qui motive un changement d’architecture. | La réglementation sur les paiements instantanés pousse MayaBank à réduire la latence et renforcer la résilience. | Goal : le Driver explique pourquoi changer ; le Goal décrit l’état souhaité. | [03-motivation](../03-motivation/README.md) |
| Assessment | évaluation / constat | Résultat d’une analyse d’un driver ou d’une situation, souvent formulé comme risque, faiblesse, force ou opportunité. | MayaBank constate que les intégrations legacy limitent le temps réel. | Gap : Assessment décrit un constat ; Gap compare deux états d’architecture. | [03-motivation](../03-motivation/README.md) |
| Goal | objectif | État futur souhaité de haut niveau. | Obtenir des paiements temps réel résilients. | Outcome : le Goal exprime une ambition ; l’Outcome est le résultat observable. | [03-motivation](../03-motivation/README.md) |
| Outcome | résultat | Résultat observable ou mesurable contribuant à un goal. | Atteindre 99,99 % de disponibilité du service de paiement. | Deliverable : Outcome est un résultat métier/architectural ; Deliverable est produit par un Work Package. | [03-motivation](../03-motivation/README.md) |
| Principle | principe | Règle durable guidant les décisions d’architecture. | Security by Design guide tous les choix de MayaBank. | Requirement : un principe oriente ; une exigence doit être satisfaite par la solution. | [03-motivation](../03-motivation/README.md) |
| Requirement | exigence | Besoin ou condition que l’architecture doit satisfaire. | RTO inférieur ou égal à 15 minutes. | Constraint : l’exigence exprime ce qui doit être obtenu ; la contrainte limite l’espace de solution. | [03-motivation](../03-motivation/README.md) |
| Constraint | contrainte | Restriction qui limite les solutions possibles. | Les données de paiement doivent rester dans l’UE. | Requirement : une contrainte restreint ; une exigence peut aussi imposer une capacité ou un niveau de service. | [03-motivation](../03-motivation/README.md) |
| Meaning | signification | Interprétation ou sens donné à une information ou à un concept. | Le score de fraude a une signification métier différente selon son seuil. | Value : Meaning concerne l’interprétation ; Value concerne l’utilité ou l’importance perçue. | [03-motivation](../03-motivation/README.md) |
| Value | valeur | Utilité, importance ou bénéfice relatif apporté à une partie prenante. | Un règlement plus rapide apporte de la valeur au client. | Outcome : la valeur est une appréciation ; l’outcome est un résultat. | [03-motivation](../03-motivation/README.md) |
| Resource | ressource | Actif possédé ou contrôlé pouvant être mobilisé pour réaliser une stratégie. | L’expertise paiements et la plateforme OpenShift sont des ressources de MayaBank. | Capability : la Resource est ce qui est disponible ; la Capability est ce que l’organisation sait faire. | [04-strategy](../04-strategy/README.md) |
| Capability | capacité | Aptitude relativement stable qu’une organisation possède pour atteindre un résultat. | Real-Time Payment Processing est une capability. | Business Process : la capability dit ce que l’organisation sait faire ; le process décrit comment elle le fait. | [04-strategy](../04-strategy/README.md) |
| Value Stream | chaîne de valeur | Séquence d’activités créant progressivement de la valeur pour un stakeholder. | Receive → Validate → Execute → Confirm décrit une chaîne de valeur paiement. | Business Process : le Value Stream raisonne valeur ; le process raisonne exécution opérationnelle. | [04-strategy](../04-strategy/README.md) |
| Course of Action | ligne d’action / orientation stratégique | Approche choisie pour atteindre un objectif ou faire évoluer des capabilities. | Adopt Event-Driven Integration est un Course of Action. | Work Package : le Course of Action est une orientation ; le Work Package est du travail planifié. | [04-strategy](../04-strategy/README.md) |
